# מכבי גבעתיים — העונה

כל העונה של הקבוצה במקום אחד: המשחק הבא, תוצאות, נתוני שחקנים, סרטונים
וקישורים. הנתונים יושבים בגוגל דרייב של המנהל; הורים ושחקנים צופים באישורו.

<https://lironcon2015-prog.github.io/MGivatayim/>

## איך זה עובד

- **הורה / שחקן** פותח את הקישור, כותב שם ("אבא של איתי") ושולח בקשה.
  אין סיסמה ואין התחברות לגוגל — המכשיר מזוהה אוטומטית.
- **המנהל** נכנס עם קוד מנהל (קישור "כניסת מנהל" בתחתית המסך), מאשר את
  הבקשה, ומאותו רגע ההורה רואה את העונה. אפשר לבטל גישה בכל רגע.
- **עדכון אחרי משחק:** מסך הניהול → "המשחק התקיים — הזנת תוצאה" → ממלאים
  את התוצאה → שמירה. נקודות, אחוזים, רצפים ופילוח בית/חוץ מחושבים לבד.

כל מכשיר מאושר בנפרד: הורה עם טלפון וטאבלט שולח בקשה מכל אחד.

## המאמן — ניהול דקות

- **הגדרה:** המאמן מבקש גישה כמו כל הורה. ניהול → גישה → בשורה שלו לוחצים
  "מאמן". מאמן עם טלפון ומחשב מסומן בכל מכשיר בנפרד. המנהל רואה את כל מסכי
  המאמן ממילא.
- **המאמן רואה** את מה שהורה רואה, ועוד דקות משחק. אין לו מסך ניהול, והוא
  לא מתעד את הלייב.
- **לפני שריקת הפתיחה:** לייב → "דקות" → הרף למשחק (ברירת מחדל 20 דקות
  במצטבר; רף שהמאמן שינה הופך לברירת המחדל של המשחקים הבאים) ומי הגיע.
- **במשחק:** רשימת כל מי שהגיע, מהכי מעט דקות, עם מי על המגרש ומי בספסל.
  מי שמתחת לרף מסומן בזהב. אין המלצות ואין סימון למי ששיחק הרבה.
- **התראה אחת:** בהפסקה שלפני השליש האחרון (במשחק של שתי מחציות — במחצית),
  אם יש בספסל שחקן שעדיין מתחת לרף. היא מציינת עד איזו דקה הוא צריך להיכנס
  כדי להגיע לרף, ומופיעה בכל מסך באפליקציה, פעם אחת.
- **בעונה:** נתונים → "דקות משחק": טבלה (משחקים, סה״כ, ממוצע, כמה פעמים
  מתחת לרף), מפה של כל העונה, והיסטוריה לכל שחקן. אחרי משחק אפשר לתקן
  נוכחות ורף מגיליון המשחק.

## משחק חי

- **פתיחה:** לשונית "לייב" → "פתיחת משחק חי". הפרטים נלקחים מהמשחק הבא,
  המבנה (למשל 3 שלישים של 30/30/20) מההגדרות. בוחרים הרכב ועמדות. אפשר לפתוח
  הרבה לפני המשחק: עד שלוחצים **"פרסום להורים"** רק המנהל, המאמן ומי שקיבל קוד
  שליטה רואים אותו. בשריקת הפתיחה הוא מתפרסם לבד.
- **במהלך המשחק:** "שער לנו" → מי הבקיע → מי בישל. "שער ליריבה" — לחיצה אחת.
  חילוף — הקשה על שחקן במגרש מציגה את הספסל בסדר: אותה עמדה (ראשית, ואז
  שנייה), העמדה הסמוכה (לקשר אחורי — קשר מרכזי), ואז לפי קווים: להגנה —
  הגנה, קישור, התקפה; להתקפה — התקפה, קישור, הגנה; לקישור — קישור, התקפה,
  הגנה. שוער לא נחשב הגנה. אותו סדר כשמתחילים מהספסל ובוחרים מי יוצא. ויש
  חיפוש לכל השאר. כל פעולה נרשמת בדקה לפי השעון, וניתנת לביטול מההודעה
  שקופצת. חילוף בהפסקה נרשם "בתחילת השליש".
- **השעון** ממשיך לספור אחרי תום השליש (תוספת זמן). אפשר לעצור, להמשיך
  ולתקן אותו ב"עוד".
- **כולם רואים בזמן אמת** — תוצאה, שעון, הרכב ומהלך המשחק.
- **אם המנהל לא מגיע:** "עוד" → "מסירת שליטה להורה" → בוחרים קוד ומוסרים
  להורה. ההורה לוחץ "יש לי קוד שליטה". הקוד עובד פעם אחת, רק למשחק הזה.
- **סיום:** התוצאה, המבקיעים, המבשלים וההרכב (ממנו הדקות) נכנסים לעונה
  אוטומטית.

**ייבוא שחקנים:** ניהול → שחקנים → "ייבוא מקובץ" (xlsx או CSV) או "הדבקה
מאקסל" (מסמנים תאים, מעתיקים, מדביקים). לפני הייבוא מוצג מה חדש ומה מתעדכן.

**עדכונים מגיעים לבד**, גם לקיצור הדרך במסך הבית — אין צורך להתקין מחדש.
מספר הגרסה מופיע בתחתית כל מסך. אפליקציה שהייתה פתוחה ברקע תיטען מחדש
כשחוזרים אליה; אם המנהל באמצע עריכה, יופיע פס "יש גרסה חדשה" במקום.

## התקנה — פעם אחת, על ידי המנהל

1. **script.google.com** → New project → מדביקים את כל התוכן של
   [`tools/bridge.gs`](tools/bridge.gs) במקום מה שיש שם.
2. **Project Settings** (גלגל שיניים משמאל) → **Script properties** →
   Add script property:
   - Property: `ADMIN_CODE`
   - Value: קוד מנהל, **12 תווים לפחות**. זה הקוד שתקלידו באפליקציה.
3. **Deploy** → **New deployment** → סוג **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
4. מאשרים את ההרשאות שגוגל מבקש (כולל "Advanced → Go to… (unsafe)" — זה
   הסקריפט שלכם).
5. מעתיקים את **Web app URL** (מסתיים ב-`/exec`) ומדביקים אותו ב-
   [`src/config.js`](src/config.js) במקום `''` — או שולחים אותו ל-Claude.

אחרי זה נכנסים לאפליקציה → "כניסת מנהל" → הקוד → ממלאים את העונה.

**אם הקובץ `bridge.gs` מתעדכן בעתיד:** Deploy → Manage deployments → עריכה
(עיפרון) → Version: **New version** → Deploy. בלי זה הכתובת מריצה את הקוד הישן.

**להחלפת קוד המנהל:** משנים את `ADMIN_CODE` ב-Script properties. נכנס לתוקף מיד.

## גלריית תמונות — הפעלה

התמונות והסרטונים שההורים מעלים **לא** נשמרים בדרייב שלכם, אלא ב-Cloudinary
(שירות אחסון תמונות, חבילה חינמית של 25GB בחודש). עד שהחיבור מוגדר, הגלריה
פשוט לא מופיעה.

1. נרשמים ב-**cloudinary.com** (חינם). עדיף עם מייל של הקבוצה.
2. ב-Dashboard (או Settings → API Keys) מעתיקים שלושה ערכים: **Cloud name**,
   **API Key**, **API Secret**.
3. ב-Apps Script → Project Settings → Script properties מוסיפים:
   - `CLOUDINARY_CLOUD` — ה-Cloud name
   - `CLOUDINARY_KEY` — ה-API Key
   - `CLOUDINARY_SECRET` — ה-API Secret (סודי: הוא נשאר בגשר, לא מגיע לטלפונים)
4. פורסים גרסה חדשה של הגשר (Deploy → Manage deployments → New version).
   בפריסה הראשונה אחרי השינוי גוגל עשוי לבקש לאשר הרשאה ל"שירות חיצוני" —
   מאשרים (הגשר מוחק דרכה קבצים מ-Cloudinary).

**בשוטף:** הורה מעלה — וזה מופיע מיד אצל כולם, עם השם שלו. כל הורה יכול
להסתיר תמונה (למשל "הילד שלי בתמונה"), והיא נעלמת מיד. מה שהוסתר מחכה לכם
בניהול → תוכן → "הוסתרו": החזרה, מחיקה, או חסימת העלאות מאותו מכשיר (בלי
לבטל לו את הגישה). שם גם מתג החירום "העלאות: פתוחות | באישור | סגורות"
והמגבלה היומית לכל טלפון (ברירת מחדל: 30 תמונות ו-3 סרטונים).

## פרטיות

האתר ציבורי, אבל **הנתונים לא**: שמות השחקנים והתוצאות יושבים בדרייב של
המנהל ומוגשים רק למכשירים שאושרו. הריפו עצמו מכיל רק קוד. דקות משחק
לשחקן מוגשות רק למנהל ולמכשירים שסומנו כמאמן. תמונות הגלריה נשמרות
ב-Cloudinary בשמות אקראיים; רשימת הגלריה מוגשת רק למכשירים שאושרו, ונתוני
המיקום מוסרים מתמונות לפני ההעלאה.
