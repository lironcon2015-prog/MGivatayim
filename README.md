# מכבי גבעתיים — העונה

עמוד אחד שמרכז את כל העונה של הקבוצה: המשחק הבא, תוצאות, נתוני שחקנים,
סרטונים וקישורים. אתר סטטי, בלי שרת ובלי שלב build.

## עדכון שבועי — `data/season.json`

זה הקובץ היחיד שצריך לגעת בו כדי לעדכן את האתר.

**אחרי משחק** — מוסיפים שורה ל-`matches`:

```json
{ "round": 8, "date": "2026-09-26", "opponent": "הפועל כוכבים", "home": true, "gf": 2, "ga": 0 }
```

`gf` = השערים שלנו, `ga` = של היריב. `home` קובע בית/חוץ. זה הכל.

**כל השאר מחושב לבד** ואין מה לעדכן ידנית: נקודות, אחוז ניצחונות, ממוצע
שערים, ספיגה, רשתות נקיות, פילוח בית/חוץ, רצפים ושיאים. אין בקובץ שדות
סיכום בכוונה — טבלאות שמתוחזקות ביד מתחילות לסתור את המשחקים שהן מסכמות.

**המשחק הבא** — `nextMatch`. `kickoff` בפורמט ISO עם אזור זמן (`+03:00`
בקיץ, `+02:00` בחורף). הספירה לאחור והשעה המוצגת נגזרות ממנו, ותמיד מוצגות
בשעון ישראל גם אם הטלפון נמצא בחו"ל.

**שחקנים** — `players`. אם סכום השערים של השחקנים לא מסתדר עם סך שערי
הקבוצה, האפליקציה אומרת את זה במסך הנתונים במקום להציג אחוזים משקריים.

**סרטונים וקישורים** — שדה `url` ריק מוצג כשורה מנוטרלת עם "טרם הוגדר
קישור", ולא כקישור שבור.

**`analysis`** — טקסט שנכתב ביד. אין כאן מודל שרץ: זה אתר סטטי בלי שרת
ובלי מפתח API. אפשר לבקש מ-Claude ניתוח על בסיס `season.json` ולהדביק את
התוצאה לכאן. (מודל חי ידרוש שרת שיחזיק מפתח — שינוי ארכיטקטורה, לא הגדרה.)

## פיתוח

```
python3 -m http.server
```

ואז <http://localhost:8000>. מודולי ES טבעיים, בלי תלויות ובלי build.

## מבנה

```
index.html              מעטפת
styles.css              טוקנים + רכיבים
src/app.js              ניתוב (#/ · #/stats · #/media) והרכבה
src/season.js           כל החישובים הנגזרים מרשימת המשחקים
src/format.js           תאריכים, שעות ומספרים בעברית
src/components.js       רכיבי UI משותפים
src/views/              home · stats · media
data/season.json        הנתונים — הקובץ היחיד לעדכון שוטף
```
