# מכבי גבעתיים — העונה

כל העונה של הקבוצה במקום אחד: המשחק הבא, תוצאות, נתוני שחקנים, סרטונים
וקישורים. הנתונים יושבים בגוגל דרייב של המנהל; הורים ושחקנים צופים באישורו.

<https://lironcon2015-prog.github.io/MGivatayim/>

## איך זה עובד

- **הורה / שחקן** פותח את הקישור, כותב שם ("אבא של איתי") ושולח בקשה.
  אין סיסמה ואין התחברות לגוגל — המכשיר מזוהה אוטומטית.
- **המנהל** נכנס עם קוד מנהל (קישור "כניסת מנהל" בתחתית המסך), מאשר את
  הבקשה, ומאותו רגע ההורה רואה את העונה. אפשר לבטל גישה בכל רגע.
- **עדכון אחרי משחק:** מסך הניהול → "המשחק התקיים — הזנת תוצאה" → ממלאים
  את התוצאה → שמירה. נקודות, אחוזים, רצפים ופילוח בית/חוץ מחושבים לבד.

כל מכשיר מאושר בנפרד: הורה עם טלפון וטאבלט שולח בקשה מכל אחד.

## המאמן — ניהול דקות

- **הגדרה:** המאמן מבקש גישה כמו כל הורה. ניהול → גישה → בשורה שלו לוחצים
  "מאמן". מאמן עם טלפון ומחשב מסומן בכל מכשיר בנפרד. המנהל רואה את כל מסכי
  המאמן ממילא.
- **המאמן רואה** את מה שהורה רואה, ועוד דקות משחק. אין לו מסך ניהול, והוא
  לא מתעד את הלייב.
- **לפני שריקת הפתיחה:** לייב → "דקות" → הרף למשחק (ברירת מחדל 20 דקות
  במצטבר; רף שהמאמן שינה הופך לברירת המחדל של המשחקים הבאים) ומי הגיע.
- **במשחק:** רשימת כל מי שהגיע, מהכי מעט דקות, עם מי על המגרש ומי בספסל.
  מי שמתחת לרף מסומן בזהב. אין המלצות ואין סימון למי ששיחק הרבה.
- **התראה אחת:** בהפסקה שלפני השליש האחרון (במשחק של שתי מחציות — במחצית),
  אם יש בספסל שחקן שעדיין מתחת לרף. היא מציינת עד איזו דקה הוא צריך להיכנס
  כדי להגיע לרף, ומופיעה בכל מסך באפליקציה, פעם אחת.
- **בעונה:** נתונים → "דקות משחק": טבלה (משחקים, סה״כ, ממוצע, כמה פעמים
  מתחת לרף), מפה של כל העונה, והיסטוריה לכל שחקן. אחרי משחק אפשר לתקן
  נוכחות ורף מגיליון המשחק.

## משחק חי

- **פתיחה:** לשונית "לייב" → "פתיחת משחק חי". הפרטים נלקחים מהמשחק הבא,
  המבנה (למשל 3 שלישים של 30/30/20) מההגדרות. בוחרים מערך (3-2-3, 4-2-2,
  4-3-1) ומכניסים אליו שחקנים: הקשה על עמדה פנויה במגרש, סימון בסגל, או
  הדבקת ההודעה של המאמן מהוואטסאפ. אפשר לפתוח
  הרבה לפני המשחק: עד שלוחצים **"פרסום להורים"** רק המנהל, המאמן ומי שקיבל קוד
  שליטה רואים אותו. בשריקת הפתיחה הוא מתפרסם לבד.
- **במהלך המשחק:** "שער לנו" → מי הבקיע → מי בישל. "שער ליריבה" — לחיצה אחת.
  חילוף — הקשה על שחקן במגרש מציגה את הספסל בסדר: אותה עמדה (ראשית, ואז
  שנייה), העמדה הסמוכה (לקשר אחורי — קשר מרכזי), ואז לפי קווים: להגנה —
  הגנה, קישור, התקפה; להתקפה — התקפה, קישור, הגנה; לקישור — קישור, התקפה,
  הגנה. שוער לא נחשב הגנה. אותו סדר כשמתחילים מהספסל ובוחרים מי יוצא. ויש
  חיפוש לכל השאר. כל פעולה נרשמת בדקה לפי השעון, וניתנת לביטול מההודעה
  שקופצת. חילוף בהפסקה נרשם "בתחילת השליש".
- **השעון** ממשיך לספור אחרי תום השליש (תוספת זמן). אפשר לעצור, להמשיך
  ולתקן אותו ב"עוד".
- **כולם רואים בזמן אמת** — תוצאה, שעון, הרכב ומהלך המשחק.
- **אם המנהל לא מגיע:** "עוד" → "מסירת שליטה להורה" → בוחרים קוד ומוסרים
  להורה. ההורה לוחץ "יש לי קוד שליטה". הקוד עובד פעם אחת, רק למשחק הזה.
- **סיום:** התוצאה, המבקיעים, המבשלים וההרכב (ממנו הדקות) נכנסים לעונה
  אוטומטית.
- **צילום Veo (כבוי כברירת מחדל):** ניהול → הגדרות → "צילום משחקים (Veo)". כשמסומן,
  מוסיפים במשחק החי קישור לשידור (בפרטי המשחק או ב"עוד"), וכל מי שצופה מקבל
  כפתור "צפייה בשידור חי". בסוף המשחק — "הוספת המשחק המצולם" מכניס את הסרטון
  לסרטונים.

**ייבוא שחקנים:** ניהול → שחקנים → "ייבוא מקובץ" (xlsx או CSV) או "הדבקה
מאקסל" (מסמנים תאים, מעתיקים, מדביקים). לפני הייבוא מוצג מה חדש ומה מתעדכן.

**עדכונים מגיעים לבד**, גם לקיצור הדרך במסך הבית — אין צורך להתקין מחדש.
מספר הגרסה מופיע בתחתית כל מסך. האפליקציה נפתחת מיד מהעותק שבטלפון, ולכן
בפתיחה הראשונה אחרי עדכון היא מציגה לכמה שניות את הגרסה הקודמת ואז נטענת
מחדש פעם אחת; אם המנהל באמצע עריכה, יופיע פס "יש גרסה חדשה" במקום.

## התקנה — פעם אחת, על ידי המנהל

1. **script.google.com** → New project → מדביקים את כל התוכן של
   [`tools/bridge.gs`](tools/bridge.gs) במקום מה שיש שם.
2. **Project Settings** (גלגל שיניים משמאל) → **Script properties** →
   Add script property:
   - Property: `ADMIN_CODE`
   - Value: קוד מנהל, **12 תווים לפחות**. זה הקוד שתקלידו באפליקציה.
3. **Deploy** → **New deployment** → סוג **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
4. מאשרים את ההרשאות שגוגל מבקש (כולל "Advanced → Go to… (unsafe)" — זה
   הסקריפט שלכם).
5. מעתיקים את **Web app URL** (מסתיים ב-`/exec`) ומדביקים אותו ב-
   [`src/config.js`](src/config.js) במקום `''` — או שולחים אותו ל-Claude.

אחרי זה נכנסים לאפליקציה → "כניסת מנהל" → הקוד → ממלאים את העונה.

**אם הקובץ `bridge.gs` מתעדכן בעתיד:** Deploy → Manage deployments → עריכה
(עיפרון) → Version: **New version** → Deploy. בלי זה הכתובת מריצה את הקוד הישן.

**להחלפת קוד המנהל:** משנים את `ADMIN_CODE` ב-Script properties. נכנס לתוקף מיד.

**מייל על בקשת גישה חדשה:** הגשר שולח מייל לחשבון הגוגל שהוא רץ בו בכל פעם
שמתקבלת בקשת גישה חדשה — לכל היותר מייל אחד בעשר דקות. בפריסה הראשונה אחרי
העדכון גוגל מבקש לאשר הרשאה חדשה ("שליחת אימייל בשמך") — מאשרים. לכתובת אחרת:
Script property בשם `NOTIFY_EMAIL` עם הכתובת; לכיבוי: `NOTIFY_EMAIL` = `off`.

## גלריית תמונות — הפעלה

התמונות והסרטונים שההורים מעלים **לא** נשמרים בדרייב שלכם, אלא ב-Cloudinary
(שירות אחסון תמונות, חבילה חינמית של 25GB בחודש). עד שהחיבור מוגדר, הגלריה
פשוט לא מופיעה.

1. נרשמים ב-**cloudinary.com** (חינם). עדיף עם מייל של הקבוצה.
2. ב-Dashboard (או Settings → API Keys) מעתיקים שלושה ערכים: **Cloud name**,
   **API Key**, **API Secret**.
3. ב-Apps Script → Project Settings → Script properties מוסיפים:
   - `CLOUDINARY_CLOUD` — ה-Cloud name
   - `CLOUDINARY_KEY` — ה-API Key
   - `CLOUDINARY_SECRET` — ה-API Secret (סודי: הוא נשאר בגשר, לא מגיע לטלפונים)
4. פורסים גרסה חדשה של הגשר (Deploy → Manage deployments → New version).
   בפריסה הראשונה אחרי השינוי גוגל עשוי לבקש לאשר הרשאה ל"שירות חיצוני" —
   מאשרים (הגשר מוחק דרכה קבצים מ-Cloudinary).

**בשוטף:** הורה מעלה — וזה מופיע מיד אצל כולם, עם השם שלו. כל הורה יכול
להסתיר תמונה (למשל "הילד שלי בתמונה"), והיא נעלמת מיד. מה שהוסתר מחכה לכם
בניהול → תוכן → "הוסתרו": החזרה, מחיקה, או חסימת העלאות מאותו מכשיר (בלי
לבטל לו את הגישה). שם גם מתג החירום "העלאות: פתוחות | באישור | סגורות"
והמגבלה היומית לכל טלפון (ברירת מחדל: 30 תמונות ו-3 סרטונים).

## השרת בקלאודפלייר — המדריך המלא

הגשר רץ היום בגוגל סקריפט. בתיקייה [`server/`](server/) יש שרת קלאודפלייר שמריץ
**את אותו קובץ גשר בדיוק**. הוא מהיר בהרבה, ובמשחק חי שולח את העדכונים לטלפונים
במקום שכל טלפון ישאל כל 4 שניות.

**אף משתמש לא עושה כלום.** אותו מפתח מכשיר, אותו קוד מנהל, אותם אישורים. עד
שלב 6 האפליקציה ממשיכה לעבוד מול גוגל כמו תמיד, ואפשר לעצור בכל שלב.

**מה צריך:** מחשב או טלפון עם דפדפן, חשבון הגוגל שבו רץ הגשר, וחשבון הגיטהאב
של הריפו. לא צריך להתקין שום דבר. בערך חצי שעה לשלבים 1–5, ועוד רבע שעה ביום המעבר.

### שלב 1 — חשבון בקלאודפלייר

1. נכנסים ל-**dash.cloudflare.com** ונרשמים (חינם). עדיף עם מייל של הקבוצה.
2. מאשרים את המייל שקלאודפלייר שולח.

### שלב 2 — חיבור הריפו, והשרת עולה

1. בתפריט: **Workers & Pages** ← **Create application**.
2. ליד **Import a repository** ← **Get started**.
3. **Connect GitHub** (בפעם הראשונה): גיטהאב שואל איזה ריפו לתת לקלאודפלייר — בוחרים
   **Only select repositories** ← `MGivatayim` ← Install.
4. בוחרים את `MGivatayim` מהרשימה. במסך ההגדרות:
   - **Project name:** `mgivatayim` — **בדיוק כך**, אותיות קטנות. שם אחר מפיל את הבנייה.
   - **Build command:** ריק.
   - **Deploy command:** להשאיר `npx wrangler deploy`.
   - **Root directory** (תחת Advanced settings): `server`
5. **Save and Deploy**. אחרי דקה-שתיים מופיע "Success" וכתובת בצורה
   `https://mgivatayim.<שם-החשבון>.workers.dev` — **מעתיקים אותה**. זו "כתובת השרת".
6. בדיקה: פותחים את הכתובת בדפדפן. צריך להופיע טקסט שמכיל `"server":"cloudflare"`.
7. מומלץ: בשרת ← **Settings** ← **Builds** ← **Branch control**: הענף הראשי `main`, ולכבות
   בנייה לענפים אחרים. כך רק מה שמוזג ל-`main` עולה.

מכאן, כל שינוי בתיקייה `server/` שמגיע ל-`main` עולה לשרת לבד. לא צריך לחזור על השלב הזה.

### שלב 3 — הצד של גוגל

נכנסים ל-**script.google.com** ופותחים את הפרויקט של הגשר.

1. **מעדכנים את `bridge.gs`:** פותחים את הקובץ הקיים, מוחקים הכל, ומדביקים את כל
   התוכן של [`tools/bridge.gs`](tools/bridge.gs) מהריפו.
2. **מוסיפים קובץ שני:** ליד "Files" לוחצים **+** ← **Script**, קוראים לו `move`, ומדביקים
   את כל התוכן של [`tools/move.gs`](tools/move.gs).
3. **Save** (סמל הדיסקט).
4. **סוד משותף:** בשורת הכלים, בתפריט הפונקציות בוחרים `newHelperToken` ← **Run**. ביומן
   למטה מופיעה שורה "HELPER_TOKEN (להעתיק לקלאודפלייר): …" — **מעתיקים את הרצף הארוך**.
   הוא כבר נשמר בגוגל לבד.
5. **Project Settings** (גלגל השיניים) ← **Script properties** ← **Add script property**:
   - `SERVER_URL` = כתובת השרת משלב 2
6. **פריסה:** **Deploy** ← **Manage deployments** ← העיפרון ליד הפריסה הקיימת ←
   Version: **New version** ← **Deploy**. **לא "New deployment"** — זו כתובת חדשה, והאפליקציה
   ממשיכה לפנות לישנה.

### שלב 4 — הסודות בקלאודפלייר

בקלאודפלייר: **Workers & Pages** ← `mgivatayim` ← **Settings** ← **Variables and Secrets** ← **Add**.
לכל אחד בוחרים **Type: Secret**, שם וערך. את הערכים מעתיקים מ-Script properties בגוגל:

| שם | ערך |
|---|---|
| `ADMIN_CODE` | **אותו** קוד מנהל שיש בגוגל |
| `CLOUDINARY_CLOUD` | כמו בגוגל |
| `CLOUDINARY_KEY` | כמו בגוגל |
| `CLOUDINARY_SECRET` | כמו בגוגל |
| `NOTIFY_EMAIL` | רק אם מוגדר בגוגל |
| `HELPER_URL` | כתובת הגשר של גוגל: `https://script.google.com/macros/s/AKfycbySPj1RCXKbzf7CIe6HlDFFnsRFDqgmGoFugT5P9T9wcCqkduS0k9rrtWVqcWYs6xnbyg/exec` |
| `HELPER_TOKEN` | הרצף מסעיף 4 בשלב 3 |
| `ALLOW_IMPORT` | `1` — רק לזמן המעבר |

**Deploy** (או Save) בסוף. סוד שנשמר נשאר גם בכל עדכון עתידי מגיטהאב.

### שלב 5 — חזרה גנרלית (כולם עדיין עובדים מול גוגל)

1. בעורך של גוגל: בוחרים `moveToServer` ← **Run**. בפעם הראשונה גוגל עשוי לבקש אישור
   ("Advanced" ← "Go to…" ← Allow). ביומן צריך להופיע **"כל טביעות האצבע תואמות"**.
2. מיד אחריו: `compareWithServer` ← **Run**. ביומן צריך להופיע **"השרתים עונים אותו דבר"**.
3. שולחים ל-Claude את כתובת השרת ואת שתי השורות מהיומן. אם יש שגיאה — את כל השורה שלה.

אפשר לחזור על השלב הזה כמה פעמים שרוצים. כל הרצה מחליפה את מה שהועתק קודם, ולא מכפילה.

### שלב 6 — יום המעבר (יום בלי משחק)

1. בגוגל, Script properties: **`MODE` = `readonly`**. מעכשיו שמירות מקבלות הודעה "האפליקציה עוברת
   לשרת חדש", וצפייה ממשיכה כרגיל. פעולה ששולט במשחק חי ביצע מחכה בטלפון שלו ונשלחת אחר כך.
2. מריצים שוב `moveToServer` ואחריו `compareWithServer`. שתי השורות הירוקות כמו בשלב 5.
3. כותבים ל-Claude: **"להחליף לשרת"**. Claude מחליף את כתובת השרת באפליקציה ומעלה גרסה.
   מחכים לאישור שלו.
4. בגוגל: **`MODE` = `forward`**. טלפון שעוד לא התעדכן ממשיך לעבוד דרך גוגל, מול השרת החדש.
5. בקלאודפלייר: מוחקים את `ALLOW_IMPORT`.
6. בגוגל: `installDailyBackup` ← **Run** (ואישור, אם גוגל מבקש). מכאן, כל לילה בסביבות 04:00
   נשמר עותק של נתוני השרת בדרייב, בתיקייה `MGivatayim-backup` (14 הימים האחרונים).
7. בטלפון: סוגרים ופותחים את האפליקציה פעמיים. בתחתית המסך — הגרסה החדשה.

**אחרי המעבר:** הגשר בגוגל ממשיך לרוץ ולא מוחקים אותו. הוא שולח את מיילי בקשת הגישה, מכין
תמונות לסרטונים מהדרייב, מגבה כל לילה, ומעביר בקשות של טלפונים ישנים.

### אם משהו לא בסדר — חזרה לגוגל

1. בגוגל: `rollbackFromServer` ← **Run**. הוא מחזיר לדרייב את הנתונים העדכניים מהשרת,
   כולל תמונות שנוצרו שם.
2. Script properties: **`MODE` ריק** (מוחקים את הערך).
3. כותבים ל-Claude: **"להחזיר לגוגל"**.

### תקלות נפוצות

| מה רואים | מה זה | מה עושים |
|---|---|---|
| הבנייה בקלאודפלייר נכשלה, ובפירוט "name" | שם השרת בקלאודפלייר אינו `mgivatayim` | Settings ← שינוי שם ל-`mgivatayim`, או לשלוח ל-Claude את השם |
| `bad_code` ביומן של גוגל | `ADMIN_CODE` בקלאודפלייר שונה מזה שבגוגל | להעתיק שוב, ולשמור |
| `import_closed` | `ALLOW_IMPORT` חסר, או לא נשמר | להוסיף `ALLOW_IMPORT` = `1`, ולשמור |
| `SERVER_URL לא הוגדר` | חסר בגוגל | שלב 3, סעיף 5 |
| "שני קבצים חיים בשם…" | יש בתיקיית הדרייב שני קבצים באותו שם | להעביר לאשפה את הישן מביניהם, ולהריץ שוב |
| "יש הבדלים בין השרתים: …" | משהו השתנה בגוגל אחרי ההעתקה | להריץ שוב `moveToServer` ואז `compareWithServer` |
| אין מייל על בקשת גישה אחרי המעבר | `HELPER_URL` או `HELPER_TOKEN` לא תואמים | להשוות לגוגל; `newHelperToken` מחדש, ולהעתיק שוב |

## פרטיות

האתר ציבורי, אבל **הנתונים לא**: שמות השחקנים והתוצאות יושבים בשרת של הקבוצה
בקלאודפלייר (וגיבוי לילי בדרייב של המנהל), ומוגשים רק למכשירים שאושרו. הריפו עצמו מכיל רק קוד. דקות משחק
לשחקן מוגשות רק למנהל ולמכשירים שסומנו כמאמן. תמונות הגלריה נשמרות
ב-Cloudinary בשמות אקראיים; רשימת הגלריה מוגשת רק למכשירים שאושרו, ונתוני
המיקום מוסרים מתמונות לפני ההעלאה.
